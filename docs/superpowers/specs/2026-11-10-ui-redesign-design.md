# PopBar UI 重设计

## 意图

PopBar 是 Windows 10/11 上常驻的原生划词工具。当前划词工具条、设置窗口和 AI 结果窗口使用少量通用 WPF 控件直接搭建，视觉层级、间距和设置组织都不够清晰。此次重设计采用 Windows 11 Fluent 风格，让界面现代、简洁、易于浏览，同时保持现有取词、操作、AI 请求与配置行为不变。

## 目标

- 为工具条、设置窗口和 AI 结果窗口建立统一的亮色、暗色视觉系统。
- 默认跟随 Windows 应用主题，并允许在设置中明确选择“跟随系统 / 亮色 / 暗色”。主题选择随其他设置保存；跟随系统时响应 Windows 主题变化。
- 工具条默认仅显示图标，以悬停提示保留完整操作名称；常用操作、AI 操作与设置之间有明确分组。
- 设置窗口改为左侧导航、右侧页面和底部固定操作区，分为“常规”“AI 服务”“提示词”三个页面。
- 提示词页面采用列表与详情编辑器，不再平铺全部提示词的全部输入框。
- 为按钮、输入框、密码框、复选框、下拉框、滚动条和工具提示建立一致的正常、悬停、按下、禁用与键盘焦点状态。
- 保持足够的文字对比度、清晰的焦点反馈和合理的点击区域。

## 非目标

- 不更改取词、全局快捷键、剪贴板、链接/路径识别、AI 协议或替换原文的逻辑。
- 不引入 Markdown 渲染、扩展市场、新的 AI 功能或新的提示词图标配置功能。
- 不引入 Electron、第三方 UI 框架或新的运行时依赖。
- 不重写 Win32 窗口附着、工具条不抢焦点和定位机制。
- 不制作自定义窗口标题栏；设置与结果窗口保留可靠的系统标题栏。

## 反目标

- 不只是更换背景色，同时保留现有平铺布局。
- 不用大量卡片、装饰性渐变或过大标题制造视觉噪音。
- 不为了仅图标工具条牺牲操作可发现性；图标必须配工具提示和无障碍名称。
- 不让暗色模式成为简单反色，也不使用低对比度灰色文字。
- 不让视觉重构改变保存校验、AI 流式输出或原选区保护行为。

## 方案比较

### 方案 A：Windows 11 Fluent 风（已选择）

使用原生 WPF 样式、统一的动态主题资源、左侧设置导航和图标工具条。符合 Windows 使用习惯，适合常驻工具，不需要新增 UI 依赖。

### 方案 B：Raycast 式极简风（未选择）

使用更紧凑的浮层、顶部标签页和折叠式提示词编辑。视觉轻盈，但设置较多时导航不如方案 A 清楚，也不如方案 A 贴合 Windows 桌面应用。

## 视觉系统

- 字体优先使用 `Segoe UI Variable`，回退到 `Segoe UI` 与 `Microsoft YaHei UI`，保证中英文显示。
- 使用语义化资源，而不是窗口各自硬编码颜色：窗口背景、表面、次级表面、主文字、次文字、边框、强调色、危险色及对应交互状态。
- 亮色使用白色/浅灰表面与深色文字；暗色使用分层深灰表面与浅色文字。强调色在两套主题下都满足可读性要求。
- 统一 4px 基础间距、适中圆角、细边框和轻量阴影。阴影主要用于浮起的工具条，不滥用在大面积设置内容上。
- 设置与结果窗口采用清晰的页面标题、简短说明、分组标题和固定底部操作区。主按钮只用于当前页面的主要提交操作。

## 划词工具条

- 保留现有条件显示规则、最多 12 个提示词、换行宽度、屏幕边界定位和不抢焦点行为。
- 所有按钮默认仅显示图标，图标字体使用 `Segoe Fluent Icons`，回退到 `Segoe MDL2 Assets`，以兼容 Windows 10/11；不增加图标资源包。
- 复制、剪切、粘贴、搜索、打开链接、文件位置和设置使用各自对应图标。
- 默认提示词“翻译 / 解释 / 润色”使用可区分图标；其他提示词使用统一 Sparkle 图标。每个按钮的工具提示及无障碍名称均使用提示词名称，因此自定义提示词不需要新增图标配置。
- 基础编辑操作、上下文操作、AI 操作和设置之间使用细分隔线；没有内容的组不留下多余分隔线。
- 按钮约 32–36px 见方，具有悬停、按下和禁用状态。工具提示包含操作全名；不增加常驻文字标签或新的显示模式。
- 工具条继续使用透明无边框顶层窗口，更新圆角表面、边框和阴影，不改变现有 Win32 激活与定位代码。

## 设置窗口

整体为“左侧导航 + 右侧滚动内容 + 底部固定按钮”。窗口尺寸以桌面内容浏览为主，保留合理最小尺寸；窗口缩小时只滚动当前内容区，导航和“取消 / 保存”始终可见。

### 常规

- 外观：下拉框提供“跟随系统”“亮色”“暗色”，默认跟随系统。
- 划词行为：保留“鼠标划词后自动弹出”和“终端中仅在按住 Shift 划词时弹出”。
- 搜索：保留带 `{text}` 占位符说明的搜索地址输入。
- 排除应用：保留进程名输入及格式说明。
- 简要展示 `Ctrl + Alt + Space` 手动唤起方式，但不占据大篇幅营销式头部。

### AI 服务

- 保留 API 基础地址、模型 ID、API Key 和清除已保存密钥。
- 保留 HTTPS、OpenAI 兼容 Chat Completions、留空保留密钥等关键说明，但用分组与次要文字减少视觉干扰。
- 字段使用明确标签和必要的示例/说明，不把所有帮助文字挤进标签本身。

### 提示词

- 页面主体左侧为提示词名称列表和“添加提示词”，右侧为当前项的名称与多行内容编辑器。
- 选择列表项后编辑对应项；添加后自动选中新项；删除当前项后选择相邻项。空列表显示简洁空状态，仍允许添加。
- 保留最多 12 项限制、名称和内容非空校验以及 `{{text}}` 替换说明。
- 所有编辑先作用于窗口内草稿；点击保存时沿用现有原子保存流程，取消不修改已保存配置。
- 删除按钮只在编辑详情区出现，避免列表每行重复操作按钮。

### 保存与主题应用

- 在 `Settings` 中增加向后兼容的主题偏好，旧配置缺少该字段时使用“跟随系统”。
- 保存时沿用现有搜索地址、AI 地址及提示词校验；保存成功后立即将新主题应用到所有窗口。
- 系统主题变化只在偏好为“跟随系统”时触发重着色，不重新创建窗口，不中断 AI 请求。

## AI 结果窗口

- 保留窗口标题、模型与字符数信息、只读流式正文、状态、停止、重试、复制、替换原文和关闭功能。
- 使用紧凑标题区、占据主要空间的正文表面、独立状态区及底部操作区。
- “替换原文”作为完成后的主要操作；“停止”仅在请求中强调；其余操作使用次级样式。
- 保留原有按钮启用规则、取消/超时/失败文案、部分结果处理和替换前选区验证。
- 正文仍可选择、复制并保持纯文本，不增加 Markdown 渲染。

## 实现边界与留给实施者的决定

- 继续使用现有 C#、WPF、.NET 8 结构。优先集中扩展 `Ui.cs` 和 `App.xaml` 的共享资源/样式，再调整三个窗口的布局；避免每个窗口复制模板。
- 可以采用小型主题管理成员和主题资源字典，具体文件组织由实施者按最小改动原则决定。
- 主题刷新必须作用于现有及后续创建的窗口；使用动态资源，不依赖逐个控件手工重着色。
- 系统主题读取使用当前用户的 Windows 应用主题设置；读取失败时采用安全默认主题，不影响启动。
- 保留系统标题栏，不投入自绘标题栏、Mica 或亚克力效果，以避免不必要的 Win32 风险和平台差异。
- 不修改无关代码、测试断言或格式。

## 验证

- `dotnet build src/PopBar -c Release` 成功。
- `dotnet run --project tests/PopBar.Tests -c Release` 通过。
- 运行 `./scripts/test-selection.ps1`，确认真实选区和替换保护未回归。
- 手动检查亮色、暗色和跟随系统，包括设置保存后立即更新、系统主题变化及新窗口继承主题。
- 手动检查工具条所有条件按钮、工具提示、换行、屏幕边界、不抢焦点，以及超过默认三个提示词时的图标识别。
- 手动检查设置三个导航页、滚动、取消、保存校验、提示词选择/添加/删除/空列表和 12 项上限。
- 手动检查结果窗口请求中、完成、停止、失败、重试、复制和可编辑/只读选区的按钮状态。
- 至少在 100% 与一个更高 DPI 下检查文字裁切、布局溢出和工具条定位。
