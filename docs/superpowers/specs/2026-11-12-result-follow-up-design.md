# AI 结果窗口连续追问设计

日期：2026-11-12
状态：已批准

## 意图

AI 结果窗口目前只展示一次回答。用户希望在同一个弹窗中继续追问，或指出回答中的问题并要求 AI 修正，避免重新划词、重新选择提示词。

## 目标

- 初始结果默认只显示正文和操作按钮，不显示追问输入框，也不提供重试按钮。
- 结果完成后显示“追问”按钮；点击后才显示多行追问输入和发送按钮，并停用当前窗口的失焦自动关闭。
- 当前窗口保存完整对话，每次追问向现有 Chat Completions 接口发送全部消息。
- Enter 发送，Shift+Enter 换行；请求期间禁止重复发送，但允许继续编辑草稿。
- 成功完成后底端不再显示“已完成”状态文字；等待、流式、停止和错误状态仍保留。
- 复制和替换原文只处理最新一轮 AI 回答的渲染后纯文本。
- 不再提供重试按钮；结果窗口的次要操作由“追问”替代。
- 停止或失败保留部分回答，并让下一轮请求包含屏幕上已显示的部分回答。
- 对话只保存在内存中，关闭窗口或发起新的 AI 操作即丢弃。
- 进入追问模式时，当前窗口立即不再因失焦自动关闭。
- 累计请求内容上限为 262,144 个 UTF-16 字符；超限提示重新发起 AI 操作，不静默截断历史。

## 非目标

- 不持久化聊天历史，不跨窗口共享会话。
- 不引入服务端会话、Responses API 或新的 Provider 协议。
- 不增加聊天气泡、WebView2、Markdown 源码切换或导出功能。
- 不改变初始提示词构造、选区读取和替换确认逻辑。

## 方案

采用现有单窗口扩展：

- `AiClient` 新增 `ChatMessage` 和消息列表请求入口；旧单轮入口作为兼容包装。
- `ResultWindow` 持有消息历史、最新回答和追问输入；复用现有流式渲染、主题、字号、取消及替换逻辑。
- 用户问题在展示时按纯文本隔离；AI 回答保留 Markdown，未闭合代码围栏只在展示副本中补齐，避免影响后续轮次。

未选择按轮次创建独立聊天控件，因为需要重写滚动、正文选择、字号和主题更新，首版收益不足。

## 交互与状态

- 初始请求保持无标签的单轮回答；发送第一条追问后，历史按“你 / AI”轮次展示。
- 请求进行中发送按钮禁用，停止按钮和输入框保持可用；完成后焦点在窗口活动时回到追问框。
- 空输入不发送；中文输入法组合中的 Enter 不发送。
- 自动关闭设置对其他窗口仍生效，仅当前已进入对话的窗口停用。
- 历史超限时保留输入内容并显示状态提示。

## 验证

- 纯逻辑和请求测试：消息顺序、旧接口兼容、用户 Markdown 隔离、未闭合围栏、历史上限。
- WPF 测试：多轮展示、重试、部分失败、停止、键盘、复制/替换、自动关闭、三语资源。
- 完整运行 `dotnet build src/PopBar -c Release`、`dotnet run --project tests/PopBar.Tests -c Release` 和 `./scripts/test-selection.ps1`。
- 手动连接真实兼容服务验证一轮追问、一次修正和替换原文。
